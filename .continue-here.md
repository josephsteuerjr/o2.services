## What changed since the last handoff, in one line each

The previous handoff's first instruction was *verify the TURN credential model before building on
it*. It was verified, it was **wrong in this tree**, and following that thread found three more
things underneath it. All of it is merged.

- **Cloudflare does not run RFC 5766.** Its credentials endpoint answers `201` with a 64-character
  opaque username and no `expiry:` prefix, so there is no shared secret to HMAC over. The API
  credential placed in the old `O2_TURN_SECRET` would have minted a well-formed credential every
  Cloudflare TURN server answers `401` to — reaching a tab as a **network fault**, past the very
  refusal written to stop it. `cloudflareTurnMinter` now asks rather than mints; two schemes, two
  names in the environment. The shipped adapter was run once against the live endpoint.
- **A deployment holding only the API key pair would have refused every mint** as
  `unknown-region`, because `turnUrlsFor` collapsed *declared with no URLs* into *undeclared*.
- **No visitor had ever asked for a TURN credential.** The rung was reachable only through
  `?turn=`, which is not in the circulated link. The endpoint is now derived from the relay the
  tab already dials, as the kill switch's is.
- **The gate admits by certificate and a visitor held none** — the one that mattered. Owner ruled
  on 2026-09-09: make enrolment real rather than loosen the gate. The hosted object now runs an
  `EnrollmentAuthority` on its own identity seed, answers AUTH-01's two frames beside the
  reservations it already served, and derives its own issuer key into the trusted set.
- **A global throttle bounds issuance, and its history survives eviction.**
  `O2_MAX_ISSUED_PER_WINDOW` is the on-switch: absent, the object signs nothing, so
  *issuing-and-unbounded* is not a state a forgotten variable can produce.
- **A reserved lane** (`O2_RESERVED_USER_KEYS`) so the operator does not queue behind the cohort.
- **A release can no longer silently switch issuance off** — see the next section; it is the one
  thing here that a reader should not skip.

Verified on this tree, both lanes, on a quiet host: **node 263 files / 3796 tests** and
**e2e 72 files / 370 tests**.

## The finding most likely to be re-broken, so it is first

`wrangler deploy` **replaces** a Worker's vars with what that invocation declares. `--var` merges
with `wrangler.jsonc` — measured and recorded in the script — but not with what a *previous*
deploy happened to set. So a budget set by a standalone
`wrangler deploy --var O2_MAX_ISSUED_PER_WINDOW:600` survives exactly until the next release.

**What that produces is worse than the loss.** Issuance stops; `deploy-pages.sh` probes `/self`,
correctly reads `issues: false`, and publishes a bootstrap document with no `enrollmentProvider`;
every visitor after that holds no certificate, so the TURN rung refuses all of them. It reads as
*TURN is broken*, with nothing naming a variable dropped two steps earlier.

`scripts/deploy-hosted.sh` now carries the vars from the environment, **refuses** a live deploy
that would turn issuance off, and reads the node back afterwards. Guarded by
`packages/node/src/deploy-preserves-enrolment.node.test.ts`. Do not "simplify" the pass-through.

## Two things to tell the owner rather than solve

- **Enrolment is unauthenticated by design** (owner decision, 2026-08-02), so anyone who can dial
  the node can consume the whole issuance window and deny honest enrolment for the rest of that
  hour. That acceptance assumed *"several independent providers coexist by construction"*. **There
  is one.** Picking the budget is picking a point on that trade; there is no value that avoids both
  harms.
- **Enrolment stays a consent question in the demo**, so TURN will reach visitors who accept the
  offer — not everyone, and not silently.

  it, which is the only safe order. `O2_TURN_SECRET` and `O2_TURN_API_SECRET` are different values
